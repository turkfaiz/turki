# مكتب رصد العمداء

نظام المرحلة الأولى لرصد 12 عمدة مختارين، ثم مراجعة الموظف للوارد والمستبعد.

## ماذا يفعل؟

- **بحث يدوي:** لا يعمل إلا بعد ضغط زر «بحث»
- **رصد مجدول:** كل أحد الساعة 06:00 بتوقيت الرياض
- **مفاتيح الرصد:** الاسم الإنجليزي + لغة أم الدولة
- **العربي:** لغة صفحة الموظف، والاسم العربي للعرض النهائي فقط
- **المصادر:** Google News + Bing News + GDELT + النطاقات الرسمية + Inoreader عند ربطه
- **النشرة:** يُقرأ جسم المقال المنظف (حتى 80 ألف حرف لكل مصدر)، وتُدمج صفحات الحدث، ثم يلخصها Gemini
- **التدقيق:** يراجع Gemini كل ادعاء في مرور مستقل، ولا يُقبل دون اقتباس حرفي من المصدر
- **الجدولة:** يوزع Queue رصد الأحد إلى مهمة مستقلة لكل مكتب حتى لا تسقط الدفعة كلها

## التشغيل المحلي

```bash
npm install
npm test
npm run dev
```

ثم افتح `http://127.0.0.1:8787`

## المفاتيح

لا تضع المفاتيح في الشات. انسخ `.dev.vars.example` إلى `.dev.vars`.

```
GEMINI_API_KEY=
GEMINI_MODEL=gemini-3.5-flash-lite
AI_DAILY_LIMIT=400
AI_MIN_INTERVAL_MS=4500
DEEPSEEK_API_KEY=
DEEPSEEK_MODEL=deepseek-flash
QWEN_API_KEY=
QWEN_MODEL=qwen-flash
```

محليًا توضع المفاتيح في `.dev.vars`. في Cloudflare المفتاح سر، والطراز متغير:

```bash
npx wrangler secret put GEMINI_API_KEY
npx wrangler secret put DEEPSEEK_API_KEY
npx wrangler secret put QWEN_API_KEY
npx wrangler secret put DASHBOARD_PASSWORD
```

الفتحات الثلاث مغلقة في الشيفرة (جيميني، ديبسيك، كوين). ربط الفتحة = سر موجود + `*_ENABLED` ليس `0`. تغيير الطراز لاحقًا من لوحة Cloudflare: `Workers` → `mayor-watch` → Settings → Variables، عدّل `DEEPSEEK_MODEL` أو `QWEN_MODEL` أو `GEMINI_MODEL` دون نشر شيفرة جديدة (`keep_vars = true`). لإيقاف فتحة مؤقتًا ضع `DEEPSEEK_ENABLED=0`.

الخبر يذهب للفتحة التي فيها سعة الآن، والطابور مشترك. قسم التفاصيل يعرض لكل نموذج: في الطابور، جاري العمل، مكتمل، تعذر.

محركات البحث معطّلة بالحوكمة. الرصد يقرأ من سجل مصادر مغلق النطاقات: ثلاثة مواقع
مفعّلة لكل مكتب على الأكثر، ولا يُفتح رابط خارجها ولا تحويل إلى نطاق آخر. وإذا لم
يوجد مفتاح Gemini تُوسم الأخبار بحالة صريحة تقول إن المفتاح غير مربوط، بدل بقائها
في انتظار صامت.

## صفحة الرصد ورحلة الرصد

الصفحة الرئيسية للمهمة الأساسية: الرصد ثم مراجعة الأخبار. الإحصاءات التشغيلية وحالة
الأدوات والمصادر انتقلت إلى الإعدادات، وبقي في الترويسة مؤشر واحد لصحة الأدوات يقود إليها.

- **شريط الأمر:** المكتب ثم الموضوع الاختياري ثم «رصد الآن».
- **رحلة الرصد:** سبع مراحل بأرقام حقيقية من الخلفية، وتتحدث كل 3.5 ثانية أثناء الرصد:
  فحص المواقع ← اكتشاف الروابط ← قراءة المقالات ← التصفية والحفظ ← كتابة الموجز ←
  التدقيق الدلالي ← جاهز للقرار. تحتها «ما يجري الآن» (المكتب والمرحلة)، وتفاصيل تُفتح
  بنقرة: أسباب الاستبعاد (لا يخص العمدة، أقدم من أسبوع، مكرر…) وحالة كل مكتب وكل موقع.
  الانتظار على حصة الذكاء يظهر «بانتظار» لا تقدمًا، ويُسجَّل الرصد الأسبوعي رحلةً مثل اليدوي.
- **سجل الرحلات:** آخر عشر رحلات، وتُفتح أي واحدة بنفس التفاصيل.
- **مكتب الأخبار:** تبويبات بعدّادات (بانتظار القرار أولًا)، وبطاقات تعرض حالة التحقق بكلمات
  بسيطة، وتفصيل لا يُفعَّل فيه الاعتماد إلا بعد اجتياز التدقيق.

الواجهة البرمجية: `GET /api/search-jobs/latest|:id?detail=1` (مصادر المهمة والقمع) و
`GET /api/search-jobs?limit=` (السجل). يعتمد القمع على فهرسي `items(scan_id)` و`candidates(scan_id)`.

## حالة الأدوات والتحقق من عملها

في الإعدادات ← «حالة الأدوات»: حماية الصفحة، قاعدة البيانات، الطابور، المجدول (نبضة يسجلها
كل تشغيل Cron في `meta`)، كل نموذج ذكاء، المواقع، قارئ الصفحات. لكل أداة قابلة للاختبار زر
«اختبار حي» يجري فحصًا حقيقيًا: قاعدة البيانات تقرأ، الطابور ومهامه العالقة، نداء فعلي صغير
للنموذج (يستهلك نداءً من حصته ويطلب تأكيدًا)، و«فحص كل المواقع» يمر على المفعّلة بطلبات حقيقية
مع تقدّم وقائمة بالمتعثر وسببه. مسار التلخيص والتدقيق وأسباب التعثر في تبويب الذكاء، ولا يُحمَّل
إلا عند فتحه لأنه يمسح جداول الأخبار.

## صفحة الإعدادات

`/settings` صفحة مستقلة (الزر «الإعدادات» في أعلى صفحة الرصد)، وكلها تقرأ من
`GET /api/settings/overview` وتكتب عبر `/api/settings/*` ثم تعيد القراءة:

| القسم | ما فيه |
|---|---|
| المكاتب والمواقع | بحث وتصفية (تحتاج انتباهًا · بلا مواقع · مضافة)، بطاقة لكل مكتب بمواقعه وحالتها، إضافة موقع، تفعيل/إيقاف، «فحص الآن»، حذف الموقع المضاف، وإضافة العمدة وتعديله وحذفه |
| الذكاء الاصطناعي | حالة كل نموذج وحصته اليوم وآخر خطأ بالعربية (للقراءة؛ المفاتيح أسرار Cloudflare) |
| النظام والسجل | الجدولة والنوافذ، زر «رصد كل المكاتب الآن»، وآخر التغييرات مع من فعلها |

عند إضافة موقع يفحصه النظام بنفسه ويختار أفضل طريقة:

1. تغذية RSS/Atom (معلنة في الصفحة أو في مسار شائع)، ثم
2. واجهة ووردبريس (`wp-json`)، وهي تعطي تاريخ كل خبر، ثم
3. صفحة الأخبار نفسها، وتُستخرج تواريخ روابطها من الرابط أو وسم `<time>` أو JSON-LD.

وإن وُجد بحث داخلي يعمل أُضيفت خطوة **تكميلية** تبحث بالاسم الإنجليزي والمحلي للعمدة
داخل الموقع نفسه، لأن قراءة آخر العناوين وحدها تفوّت خبر العمدة بين مئات الأخبار.
ثم يُجرَّب الموقع بنفس محرك الرصد: إن لم يعمل لا يُحفظ، وتظهر في الواجهة نتيجة التجربة.
بعدها يعمل تلقائيًا: Cron الأحد يمرّ على كل المكاتب بما فيها المضافة، دون نشر جديد.

الحدود: ثلاثة مواقع **مفعّلة** لكل مكتب (أوقف موقعًا أو احذفه لتفريغ خانة)، ولا تُقبل
عناوين IP ولا شبكات داخلية ولا محركات بحث ولا منصات تواصل ومدونات عامة. وهوية العمدة
إلزامية في كل خبر مهما كان مصدره. كل تغيير مسجّل في `settings_audit`. مصادر السجل المكتوب
في `src/sources.js` تُوقَف ولا تُحذف، ولا يُعدَّل أو يُحذف عمدة السجل الأساسي. ولا يُحذف
عمدة مضاف له قرارات محفوظة.

`npm run check:sources -- <office-id>` يفحص مصادر مكتب بالمحرك نفسه من جهازك.

## مستوى التحقق في الموجز

الموجز يمر بمرحلتين محفوظتين، وكل منهما تُستأنف من موضعها:

| المرحلة | ما تضمنه | الشارة |
|---|---|---|
| الإسناد المحلي | كل عنوان وحقيقة يحمل اقتباسًا موجودًا **حرفيًا** في نص المصدر ويشير إلى العمدة | «موجز مسند — بانتظار التدقيق الدلالي» |
| التدقيق الدلالي | نداء مستقل يقرر هل يقول الاقتباس فعلًا ما يدّعيه النص العربي، فيرفض قلب النفي أو تغيير الرقم أو الفاعل | «موجز مدقَّق — مسند ومُتحقق دلاليًا» |

وجود الاقتباس حرفيًا **لا يكفي** دليلًا على صحة الاستنتاج العربي، ولهذا لا يصبح
الموجز جاهزًا للاعتماد قبل اجتياز التدقيق الدلالي، وواجهة الاعتماد معطّلة قبله.

## الاعتماد والأرشيف

كل موجز يُحفظ كنسخة مستقلة في `brief_versions` قبل التدقيق، فلا يُفقد إن تعذّر
النداء الثاني. وقرار الموظف يُسجَّل في `approvals` مرتبطًا بنسخة محددة، مع هوية
المراجع ووقت القرار وصورة مجمّدة للنص والأدلة والمصدر. فإن تغيّر المصدر بعد
الاعتماد نشأت نسخة جديدة تحتاج مراجعة، وبقيت النسخة المعتمدة وأدلتها كما هي.

نافذة الرصد سبعة أيام والتقليم بعد تسعة، لكن **أي خبر يحمل قرارًا محفوظًا لا
يُحذف** — النافذة للعرض والأرشيف للقرارات. وإعادة الضبط إجراء إداري صريح عبر
`POST /api/admin/reset` بتأكيد نصي، ولا تقع ضمن أي مسار قراءة أو ترحيل.

المكتب يعرض أربع مسارات تشغيلية مستقلة، و`status=inbox` في الواجهة البرمجية
يعني **بانتظار القرار** لا كل الوارد:

| المسار | الشرط |
|---|---|
| `reading` | الخبر داخل النافذة وما زال يُقرأ أو يُلخَّص |
| `verifying` | توجد نسخة حالية و`verify_state = pending` |
| `decision_ready` | نسخة حالية + `verify_state = passed` + داخل نافذة العرض |
| `attention_required` | تعثر أو استنفاد أو موجز بلا نسخة محفوظة |

اكتمال `trans_engine` وحده **لا** يُدخل الخبر إلى بانتظار القرار. bootstrap
additive: لا يمسح `items` ولا `approvals` ولا `brief_versions` ولا `scans`
ولا `jobs`، ولا يصفّر حصص الذكاء الاصطناعي. تقرير dry-run متاح من
`GET /api/admin/migrations/desk-lanes`.

قبل أول نشر أنشئ طابور Cloudflare المعرّف في `wrangler.toml`:

```bash
npx wrangler queues create mayor-watch-scans
```

عند ضبط `DASHBOARD_PASSWORD` يحمي Worker الصفحة وكل واجهات التعديل بمصادقة المتصفح
الأساسية. اسم المستخدم الافتراضي `mayorwatch` ويمكن تغييره عبر `DASHBOARD_USER`.
يمكن وضع Cloudflare Access أمامها كطبقة إضافية في النشر المؤسسي.

حماية الصفحة إلزامية عند وجود أي مفتاح ذكاء اصطناعي: إذا ضُبط المفتاح دون
`DASHBOARD_PASSWORD` يرفض Worker طلبات الويب حتى لا تصبح التكلفة وقرارات الاعتماد عامة.

## بنية الشيفرة

| الملف | الدور |
|---|---|
| `src/worker.js` | نقطة الدخول فقط: `fetch` و`scheduled` و`queue` (نحو 100 سطر) |
| `src/config.js` | ثوابت الجدولة والنوافذ والدفعات |
| `src/db/` | `schema.js` الجداول · `bootstrap.js` `ensureDb` · `migrations.js` الترحيل additive · `items.js` التقليم وسجل صحة المصادر |
| `src/jobs/` | `enqueue.js` إرسال المهام · `consumers.js` معالجة رسائل Queue · `desk.js` إنهاء المكتب والتصريف · `continuation.js` قرار الاستكمال · `searchJob.js` حالة مهمة البحث |
| `src/api/` | `http.js` المصادقة والاستجابة · `status.js` الصحة والإحصاءات والتشخيص · `settings.js` واجهة الإعدادات · `tools.js` حالة الأدوات واختباراتها الحية · `routes.js` بقية مسارات `/api/*` |
| `src/pipeline.js` | الرصد → المرشحون → قراءة المقال (يستورده Worker مباشرة) |
| `src/sources.js` · `discovery.js` · `newsroom.js` · `rss.js` · `sitemap.js` | سجل المصادر واكتشاف الروابط |
| `src/sourceProbe.js` · `sourceAdmin.js` · `mayorAdmin.js` · `db/customSources.js` | فحص المواقع المضافة وإضافتها وحذفها وفحصها الفوري، وإدارة العمداء المضافين، وتحميلها من D1 |
| `public/index.html` · `app.js` · `journey.js` · `desk.js` · `lib.js` | صفحة الرصد: التفاعل في `app.js`، ورحلة الرصد في `journey.js`، وبطاقات الأخبار في `desk.js` (دوال العرض نقية وتُختبر دون متصفح) |
| `public/settings.html` · `settings.js` · `settings.css` | صفحة الإعدادات |
| `src/article.js` · `governedFetch.js` | قراءة المقال تحت الحوكمة |
| `src/translate.js` · `aiBrief.js` · `aiDispatch.js` · `aiBudget.js` · `aiProviders.js` | الموجز والتدقيق الدلالي وتوزيع الفتحات والحصص |
| `src/versions.js` · `deskLanes.js` · `journey.js` | النسخ والاعتماد ومسارات المكتب ورحلة الخبر |
| `src/brief.js` · `reviewAgent.js` | كشف الموضوع وتجميع الأخبار المكررة في الوارد |

تعمل `npm test` و`wrangler deploy --dry-run` تلقائيًا على GitHub Actions
(`.github/workflows/ci.yml`) لكل دفعة وكل طلب دمج.

## الجدول

Cron على Cloudflare: `0 3 * * SUN` = الأحد 03:00 UTC = الأحد 06:00 في الرياض.
